# Migration: finngenie.broadinstitute.org → genegenie.broadinstitute.org (daly)

Goal: serve the daly deployment at `genegenie.broadinstitute.org` and make
`finngenie.broadinstitute.org` issue a 301 redirect to it (browser URL changes,
path + query preserved).

## How the daly deployment is wired (background)

Production is GKE Ingress, not the legacy VM/nginx setup in `nginx-setup.md`:

- Global static IP `finngenie-ip` (terraform `var.static_ip_name`, referenced as a
  `data` source in `terraform/main.tf` — reserved outside this state).
- GKE Ingress + Google-managed certificate, both generated by `scripts/deploy.sh`
  from the `domains` list in the daly `terraform.tfvars`.
- oauth2-proxy (Google OAuth) gates everything; callback is
  `https://<domain>/oauth2/callback`.
- DNS: `broadinstitute.org` is managed by Broad IT, **not** in this repo (there is
  no Cloud DNS zone in terraform). The A record points the host at the static IP.

A hostname is "live" only when all four align: DNS A record → static IP, host in the
managed cert, host as an Ingress rule, and the host's callback URL allowed on the
OAuth client.

## Phase 1 — bring genegenie up alongside finngenie

1. **DNS (Broad IT — external, longest lead time).** Request an A record
   `genegenie.broadinstitute.org` → the **same static IP** as finngenie (one LB
   serves both; no new IP). Get the IP with:
   ```bash
   cd terraform && terraform output -raw static_ip
   ```

2. **Add genegenie to the cert + ingress.** In the daly `terraform.tfvars`:
   ```hcl
   domains = ["finngenie.broadinstitute.org", "genegenie.broadinstitute.org"]
   ```
   Then `./scripts/deploy.sh` regenerates the `ManagedCertificate` and `Ingress`
   with both hosts. The managed cert will **not** go `Active` for genegenie until
   its DNS A record already resolves to the LB IP, so do step 1 first. Expect
   ~15–60 min provisioning. Check:
   ```bash
   kubectl describe managedcertificate managed-cert -n genetics
   ```

3. **OAuth redirect URI.** In the GCP project's APIs & Services → Credentials,
   edit the OAuth client used by oauth2-proxy and add
   `https://genegenie.broadinstitute.org/oauth2/callback` to Authorized redirect
   URIs (and the origin to Authorized JavaScript origins if applicable). Without
   this, login on the new host fails with `redirect_uri_mismatch`.

After Phase 1, both hostnames serve the app identically.

## Phase 2 — make finngenie redirect to genegenie

Keep `finngenie.broadinstitute.org` in the `domains` list so its cert stays valid
and the redirect is served over HTTPS. Add a host-based 301 in the auth-gateway
nginx config (`k8s/deployments/auth-gateway.yaml`, inside the `server { listen 8080; }`
block), before the other location rules:

```nginx
if ($host = finngenie.broadinstitute.org) {
    return 301 https://genegenie.broadinstitute.org$request_uri;
}
```

Apply with:
```bash
./scripts/rollout.sh auth-gateway
```

The GKE Ingress cannot do host-rewrite redirects itself (FrontendConfig only does
HTTP→HTTPS), so this nginx layer is the right place.

## Notes

- DNS is the only piece outside our control — `genegenie` A record is a ticket to
  Broad IT.
- **Do not drop finngenie from the cert** even after cutover, or the redirect
  itself breaks with a TLS error.
- Smallest first step (when ready): file the DNS request (longest lead time) in
  parallel with adding genegenie to `domains` and the OAuth client.
