# Legacy hostname redirect: finngenie.broadinstitute.org → genegenie.broadinstitute.org

The daly deployment was migrated from `finngenie.broadinstitute.org` to
`genegenie.broadinstitute.org`. **The migration is complete** — this file is the record of
why the redirect configuration still exists and must stay in place.

`finngenie.broadinstitute.org` issues a 301 to `genegenie.broadinstitute.org`, preserving path
and query string (`finngenie…/chat/XXX?foo=bar` → `genegenie…/chat/XXX?foo=bar`).

## What implements it

The redirect is profile-driven, so it never leaks into other deployments (finngen sets neither
variable; they default to `""`).

| Piece | Where |
| --- | --- |
| `redirect_from_host` / `redirect_to_host` | `terraform/variables.tf`, exposed in `terraform/outputs.tf`; set to finngenie/genegenie in `terraform/terraform.tfvars.daly` |
| `LEGACY_REDIRECT` nginx snippet | rendered by `scripts/deploy.sh` from those two outputs (empty when unset) |
| `${LEGACY_REDIRECT}` placeholder | `k8s/deployments/auth-gateway.yaml`, inside `server { listen 8080; }` |

The rendered snippet is:

```nginx
if ($host = finngenie.broadinstitute.org) {
    return 301 https://genegenie.broadinstitute.org$request_uri;
}
```

The `$host` guard means only finngenie requests redirect; GKE backend health checks (which hit
`/healthz` with the node IP as Host) are unaffected. The GKE Ingress cannot do host-rewrite
redirects itself (FrontendConfig only does HTTP→HTTPS), so this nginx layer is the right place.

`redirect_to_host` is also the *canonical web host*: `deploy.sh` derives `KEYCLOAK_HOST` and the
Keycloak realm's oauth2-proxy callback from `${REDIRECT_TO_HOST:-${DOMAIN}}`, so those never point
at the host that redirects away.

## Constraints to preserve

- **Keep `finngenie.broadinstitute.org` in the daly `domains` list.** Dropping it invalidates its
  managed certificate, and the redirect itself then fails with a TLS error before nginx ever sees
  the request.
- Both hostnames resolve to the same static IP (one load balancer serves both). DNS for
  `broadinstitute.org` is managed by Broad IT, not by this repo — there is no Cloud DNS zone in
  terraform.
- Applying `auth-gateway.yaml` requires `envsubst` (it contains `${LEGACY_REDIRECT}`), so a plain
  `kubectl apply -f k8s/deployments/auth-gateway.yaml` will not work. `scripts/rollout.sh` also
  cannot update it — that only swaps container images. Use `./scripts/deploy.sh`.

## Related

Production is GKE Ingress + a Google-managed certificate generated by `scripts/deploy.sh` from the
`domains` list. Browser sessions are gated by oauth2-proxy, whose provider is profile-driven
(`oidc` against Keycloak on daly, where `ENABLE_KEYCLOAK` defaults to true; `google` directly
otherwise) — see [keycloak-apple-signin.md](keycloak-apple-signin.md).
[nginx-setup.md](nginx-setup.md) documents the superseded VM/nginx setup and does not apply here.
