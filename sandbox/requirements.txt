# analysis dependencies for the sandbox image, installed into /opt/venv in the
# builder stage. pinned exactly: the image is a security boundary and an
# unpinned resolve would change the syscall surface silently between builds.
#
# nothing google-auth-based may appear here or in any transitive closure —
# docs/code-execution-security.md section 3(c): google.auth.default() probes
# metadata.google.internal by name, and the sandbox has no DNS, so the probe
# stalls the full resolver timeout instead of failing fast. build-checks.py
# fails the build if it reappears.
#
# the set is CLOSED at numpy/scipy/polars/matplotlib/httpx: this file declares the SDK's real
# runtime closure (docs/code-execution-security.md, "Deviation 2" — the SDK is installed
# --no-deps), not a convenience toolbox. pandas is absent BY DESIGN and not by oversight —
# polars is the frame type every SDK function returns, so a second dataframe library would add
# image size and syscall surface to a boundary image for nothing.
numpy==2.4.6
scipy==1.17.1
polars==1.40.1
matplotlib==3.10.9
httpx==0.28.1
#
# scienceplots is the one deliberate opening of that set, and the test it was admitted under is
# the one the paragraph above applies: does it widen what the boundary image can DO? It ships 47
# .mplstyle files and an __init__ that registers them in plt.style.library. No native code, no
# imports beyond matplotlib (already pinned), nothing that opens a socket or a file outside its
# own package. That is a different category from pandas, which would have been a second
# implementation of the thing polars already is. It is OPT-IN: the baked matplotlibrc carries
# render density and no style, and a script that wants one writes plt.style.use("science").
# Imposed as a default it made some figures worse — a locuszoom reads by its LD ramp and marker
# shapes, not by journal typography — and a default a caller has to notice and undo is worse
# than one they ask for.
#
# `science` alone CANNOT be used here: it ends with text.usetex:True and this image is
# distroless with no LaTeX and no shell to run one, so a script asking for it must pair it with
# no-latex: plt.style.use(["science", "no-latex"]). That pairing is now the script's to write,
# which is the cost of making the style opt-in.
scienceplots==2.2.2
#
# When a genetics-mcp-server import argues for a line here, the answer is to cut the module
# that does the importing out of the SDK's import closure, not to add the pin: adding it
# widens a security-boundary image to satisfy an import the boundary never needed. Every such
# argument so far has been answerable that way — a lazy re-export, a TYPE_CHECKING guard, a
# subclass — and no pin proposed by one exists here, dormant or otherwise.
#
# genetics-mcp-server's tests/test_sdk_import_closure.py asserts the SDK imports with every
# module outside this file's surface unavailable, so a MODULE-LEVEL offender fails there rather
# than arriving here as a proposed line. That check runs the import, so it sees only what the
# import runs; a DEFERRED import executes at call time and is invisible to it. The same test
# and build-checks.py therefore also PARSE every shipped file and refuse an import of anything
# outside that surface at any nesting depth, which is what a deferred import fails. Failing the
# build is the point, not the pin it seems to ask for: the answer to a deferred import is that
# the code holding it should not be in the image at all.
