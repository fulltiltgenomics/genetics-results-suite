# stalls the full resolver timeout instead of failing fast. build-checks.py
# fails the build if it reappears.

# the set is CLOSED at numpy/scipy/polars/matplotlib/httpx: this file declares the SDK's real
# runtime closure (docs/code-execution-security.md, "Deviation 2" — the SDK is installed
# --no-deps), not a convenience toolbox. pandas is absent BY DESIGN and not by oversight —
# polars is the frame type every SDK function returns, so a second dataframe library would add
# image size and syscall surface to a boundary image for nothing.
numpy==2.4.6
scipy==1.17.1
polars==1.40.1
matplotlib==3.10.9
httpx==0.28.1

# When a genetics-mcp-server import argues for a line here, the answer is to cut the module
# that does the importing out of the SDK's import closure, not to add the pin: adding it
# widens a security-boundary image to satisfy an import the boundary never needed. Every such
# argument so far has been answerable that way — a lazy re-export, a TYPE_CHECKING guard, a
# subclass — and no pin proposed by one exists here, dormant or otherwise.
#
# genetics-mcp-server's tests/test_sdk_import_closure.py asserts the SDK imports with EVERY
# distribution outside this file's dependency closure unavailable, so a MODULE-LEVEL offender
# fails there rather than arriving here as a proposed line. It structurally cannot see a
# DEFERRED import: that runs at call time, so `import genetics_mcp_server.sdk` proves nothing
# about it and the failure surfaces in the deployed image instead. Nothing here can be made
# to catch that, so what has to answer for a deferred import is that the code holding it is
# not in the image at all — keep it out rather than pinning for it.
